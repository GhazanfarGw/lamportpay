# Pre-LIVE security checklist

Updated: 7 Oct 2026 (round 2). Environment reviewed: dev (TEST MODE, Supabase dev project,
Stables sandbox). This is an engineering self-review, **not** an independent security audit; an
external review is still required before real customer funds.

Legend: **PASS** = verified in code/tests/database · **FAIL** = must be fixed before LIVE ·
**NEEDS REVIEW** = not verified or needs a decision.

| #   | Area                                   | Status                  | Evidence / note                                                                                                                                                                                                                                                                                                                           |
| --- | -------------------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Authentication                         | PASS                    | Every API route and server function verifies the Supabase JWT (`getClaims`); `tests/payments.test.ts` rejects missing and forged tokens                                                                                                                                                                                                   |
| 2   | Admin authorization                    | PASS                    | `has_role(admin)` in every admin server function (cases, controls, reports, settings) plus admin-only RLS                                                                                                                                                                                                                                 |
| 3   | RLS on every table                     | PASS                    | Checked table by table on the dev DB (7 Oct): RLS on all 19 public tables; users read only their own payments, events, customers, wallets, swaps; cases/controls/reports admin-only; `rate_limit_buckets`, `business_settings`, `jupiter_swap_orders` service-role only                                                                   |
| 4   | Table grants (defense in depth)        | PASS (fixed round 2)    | Removed leftover `anon` grants on 5 tables and all client grants on the old demo tables (`20261007140000_privilege_hardening.sql`)                                                                                                                                                                                                        |
| 5   | IDOR / payment ownership               | PASS                    | `ownedPayment` (payment ID + user ID) on every payment endpoint; malformed IDs answer 404                                                                                                                                                                                                                                                 |
| 6   | Wallet ↔ payment ↔ transaction binding | PASS                    | Payer must be the payment's wallet (linked wallet for wallet accounts); deposit must be signed by it; exact amount, mint and Stables deposit address; finalized; `funding_signature` unique (DB) and checked before and during the write (`signature_taken`)                                                                              |
| 7   | Transaction replay / reuse             | PASS                    | Unique `funding_signature`, unique `transfer_id`, unique Jupiter request IDs and swap signatures; a TEST Pay Now memo transaction is accepted once per payment                                                                                                                                                                            |
| 8   | Duplicate submission / races           | PASS (partial)          | All state changes are compare-and-set on the current status (`.eq("status", from)`); Pay Now single-fire; per-user creation limit (10/min). NEEDS REVIEW: no idempotency key on payment creation (a double submit creates two unpaid payments; no double charge is possible)                                                              |
| 9   | Amount manipulation                    | PASS                    | Server computes every amount; quote fixed at transfer creation; deposit amount checked against the quote; limits (coin + corridor) enforced on the server                                                                                                                                                                                 |
| 10  | Webhook authenticity / replay          | PASS                    | Svix HMAC-SHA256, 5-minute timestamp tolerance, dedupe by `event_id`, 401 for unsigned/forged; **new:** 256 KB body cap and per-IP rate limit before signature work                                                                                                                                                                       |
| 11  | Rate limiting                          | PASS (fixed round 2)    | Platform-wide limiter in Postgres shared by all instances (per user: 120/min on all payment/KYC routes; 10 create, 20 quote, 10 transfer, 20 funding, 10 KYC); public estimate/balance limits now shared; webhook per-IP; fallback to per-instance limit if the DB is down. NEEDS REVIEW: no limit on admin server functions (admin-only) |
| 12  | Input validation                       | PASS                    | zod on every route and server function; currency/amount/address regexes; case and control fields validated server-side                                                                                                                                                                                                                    |
| 13  | Security headers                       | PASS (fixed round 2)    | Every response: `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, HSTS, COOP `same-origin-allow-popups` (wallet popups keep working). NEEDS REVIEW: full script/connect CSP (report-only trial first)                                                                                |
| 14  | CORS                                   | PASS                    | No `Access-Control-Allow-Origin` anywhere: same-origin only                                                                                                                                                                                                                                                                               |
| 15  | CSRF                                   | PASS                    | Bearer token in `Authorization`, not cookies                                                                                                                                                                                                                                                                                              |
| 16  | XSS                                    | PASS                    | React escaping; TanStack Start XSS advisory patched (4 Oct); CSV export neutralizes spreadsheet formulas                                                                                                                                                                                                                                  |
| 17  | SQL injection                          | PASS                    | Supabase query builder only; SQL functions take typed parameters                                                                                                                                                                                                                                                                          |
| 18  | Secrets / env exposure                 | PASS                    | `.env` git-ignored; only `VITE_*` values reach the browser (publishable values); secret scans clean; Vault holds the scheduler's cron secret; LIVE keys refused in TEST MODE                                                                                                                                                              |
| 19  | Dependency vulnerabilities             | NEEDS REVIEW (improved) | `npm audit fix` (non-breaking): critical 1 → 0, high 14 → 13. Remaining: `braces` (no patched version yet; build tooling via React Native/Metro under `@solana-mobile`) and `stream-json` (via `@solana/web3.js` → `jayson`; parses responses from our own RPC provider). No fix without breaking major upgrades                          |
| 20  | Error leakage                          | PASS (partial)          | Unexpected errors return a generic message and are logged server-side; NEEDS REVIEW: Stables error texts shown to users on refusals                                                                                                                                                                                                       |
| 21  | Audit logging                          | PASS                    | Append-only admin audit log; case history append-only; controls changes and CSV exports audited                                                                                                                                                                                                                                           |
| 22  | Leaked-password protection             | FAIL (owner action)     | Disabled. Cannot be changed from the tools available here: Supabase Dashboard → Authentication → Providers/Password security → enable "Leaked password protection"                                                                                                                                                                        |
| 23  | Admin MFA                              | NEEDS REVIEW            | Not enforced for admin accounts                                                                                                                                                                                                                                                                                                           |
| 24  | Logging hygiene                        | PASS                    | IDs only (payment, transfer, correlation, svix); rate-limit refusals log the key kind, not the user/IP; bank details stored masked; KYC documents never reach LamportPay                                                                                                                                                                  |
| 25  | KYC data minimization                  | PASS                    | Stored: Stables customer ID, verification statuses, first/last name (for the own-account payout holder name), hosted KYC link + expiry, timestamps. No documents, no dates of birth, no ID numbers                                                                                                                                        |
| 26  | Unused privileged code                 | PASS                    | Legacy demo-table admin functions removed (round 1)                                                                                                                                                                                                                                                                                       |
| 27  | `has_role` callable by signed-in users | PASS (accepted)         | Restricted to the caller's own roles                                                                                                                                                                                                                                                                                                      |

## Before LIVE

Close #22 (owner action), decide #19 (accept with justification or upgrade), #23, the CSP trial
in #13 and the idempotency key in #8, then an independent security review.
